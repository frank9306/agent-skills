# Requirement Questioning Discipline

Maintain four lists while clarifying:

- Facts: supported by repository evidence or an authoritative source.
- Decisions: choices only the user or accountable stakeholder can make.
- Assumptions: temporary defaults that must be confirmed or made harmless.
- Frontier: unresolved branches that can still change behavior, scope, data, or verification.

Ask about the highest-impact frontier item first. Do not ask where code lives, what framework is installed, or anything else repository inspection can answer. Prefer concrete scenarios over abstract preference questions.

A requirement is Issue-ready when a fresh agent can understand why the work exists, describe successful and unsuccessful behavior, identify what is excluded, and verify completion without reading the original conversation.
