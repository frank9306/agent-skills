# Comp before build：在 CSS 中组合之前以像素形式组合

**仅**当预检发现 `TOGETHER_API_KEY` (signal 9) 时加载：在“精选”块之后的合成步骤中，以及生成的静态图片（末尾的「生成静态图像」）。如果没有密钥，此文件永远不会加载，并且构建会从 设计决策清单直接进入步骤 6。comp 步骤永远不会成为障碍，也永远不会因跳过而道歉。

渲染的伴奏一目了然地带有质量、音程和对齐方式，这是散文所不能的；复制经过批准的图像比根据段落发明构图更容易。

---

## § 补偿是什么，不是什么

| 这是 | 它不是 |
| --- | --- |
| 构图建议：质量、间隔、对齐、眼睛首先关注的位置 | 设计系统；调色板和配对已固定在“精选”块中并且不会移动 |
| 仅第一个视口，以表面自身的尺寸 | 整页；在首屏下竞争不会购买任何东西，并且需要按区域拨打电话 |
| 在代码中重现的目标，衡量标准 | 纹理源；页面中没有嵌入任何内容 |
| 一旦构建匹配即可丢弃 | 一项资产；补偿未发货且未提交 |

**该比较没有对 Floor 进行投票。** 图像生成器将为您提供标题上方的短标签、紫罗兰色到青色的渐变、玻璃形态和假浏览器窗口，因为其中没有任何内容读取门。与存档范例相同的规则：**采用其组成，而不是其合规性。** 比较永远不会证明门是错误的，并且“比较有它”并不是放弃的理由。

## § 调用方式

两个比较，当方向真正分叉时三个。一是不选择，四是购物之旅。

```
node <skill-dir>/scripts/imagegen.mjs "<prompt>" --size 1280x800 --n 1 --out .hallmark/comps/c1.png
```

提示是根据设计决策清单和设计记录的想法或主题行构建的，而不是根据提示构建的。读起来像提示的提示会生成以像素为单位的默认类别，页面 `direction.md` 预留。按此顺序进行：您计划的**第一个视口**（位于何处，有多大），**想法**用几个简单的单词表示，**背景和重音**作为纯色单词，**显示类**（不是面孔名称；没有生成器知道Erode），以及**宏观结构**作为组合指令。然后一个否定子句命名了类别的作用，因此生成器也被推离了类别。

> *“网页首屏主视觉，仅限顶部 1280x800。赛艇俱乐部的赛季设置为一个大型比赛时间表，下一场比赛是屏幕上最大的一条线。白色底色，深绿色墨水，一个信号黄色标记。粗大的粗体标题向左齐平，五列，两行；时间表在其他七行上。标题下有一条细线，折叠上方没有其他内容。平面，印刷，没有深度。不是居中的首屏主视觉，没有卡片，没有渐变，没有设备样机。”*

**仅改变一个轴上的比较。** 两个在所有方面都不同的比较是两个提示，对它们进行比较不会告诉您任何有关您实际做出的决定的信息。改变构图（重量所在的位置、对称与不对称、类型主导与图像主导）并保持系统固定。

## § 审批点

以各自的尺寸并排显示两者。不同之处各占一行。然后停下来问是哪一个，或者两者都不是。

这是第二个也是最后一个重定向窗口（设计决策清单是第一个），它比构建后的重定向窗口便宜得多。 **不要构建超出用户未选择的组合。**“我将构建 A，我们可以调整”是批准点变成装饰的方式。

如果用户两者都不选择，请询问哪个在构图上更接近，更改该轴，然后重新调用一次。两轮就是上限；之后，在没有comp的情况下构建并在一行中这么说。

## § 设计稿复现要求

**当模型没有成功时，模型可靠地相信它的重建成功了。**这是一种失败模式，如果不加防范，整个步骤就会变得毫无价值，因为信念会阻止你寻找。

因此，在构建任何以下内容之前：

1. 在**确切的组件尺寸** (1280x800) 处对构建的页面进行屏幕截图。
2. 将两者并排放置，并以书面形式回答三个问题，每行一行：
   - **质量。** 重量相对于视口是否处于相同位置、相同大小？
   - **间隔。** 主要元素之间的间隙与高度的比例是否相同？
   - **条目。** 目光首先落在同一个元素上吗？
3. 指出最大的差异并修复它，或者在一行中说明为什么构建版本是正确的而比较是错误的。两者都是合法的。沉默则不然。

作品是目标，而不是权威：复制一个错误判断了副本长度的作品比故意偏离它更糟糕。被禁止的东西在不知不觉中就发生了分歧。

将其记录在设计记录中：`comp: 2 rendered · c1 approved · reproduced (checked at 1280x800)`、或`comp: skipped (no key)`、或`comp: 2 rendered · none approved · built unconstrained`。

## § 介质库存

在编写一行构建之前，批准的组件的每个区域都会获得书面的实现介质。六八个区域，每个区域一条线，大约需要一分钟。

**门：CSS渐变或分层背景不是纹理。** 在编织布、雕刻面板、印刷半色调、拍照材料或任何带有纹理的东西上写“CSS”，就是一个承诺的设计如何默默地变成一个具有相同部分顺序的平面页面，并且没有任何雄心壮志。库存的存在是为了让这种替代品在价格仍然便宜的情况下可见。

| 中等的 | 它适合做什么 |
| --- | --- |
| **代码** (CSS/SVG) | 页面*绘制*的内容：规则、类型、几何图形、图表、任何动画或反应的内容、任何必须重排的内容 |
| **光栅**（生成或提供） | 世界*描绘*：材料、纹理、布料、纸纤维、摄影、绘画或雕刻表面、真实深度 |
| **两者都不** | 比较发明的区域，但副本不支持。在这里剪切，而不是在构建之后剪切 |

上面有两条规则：

- **栅格区域需要真实的源：**用户提供的资源、库照片 (`imagery.md` § 2) 或生成的静态图片（§ 生成的静态图片）。记忆中的照片不是来源，并且合成图绘制的区域永远不会成为绘图 (80)。
- **区域无法在构建过程中默默地更改介质。** 在构建过程中将光栅降级为 CSS 是本节捕获的全部失败。如果代码有争议，请更改它，并在一行中说明这一点。

将库存作为赠品消息的一部分发送，在赠品下：

```
Timetable          code      a real table, must reflow
Headline           code      type, must reflow
Rule under head    code      1px, tokenised
Next-race mark     code      the accent on one row, it moves once on load
Rower photograph   raster    library photo; the comp's crew is not a real crew
```

## § 生成静态图像

页面本身的图片，在合成步骤之外：仅当设置了 `TOGETHER_API_KEY` 并且用户要求生成图像时，或者对于库无法到达 (`imagery.md` § 1) 的主题时。

```
node <skill-dir>/scripts/imagegen.mjs "<prompt>" --size 1536x1024 --out <project>/images/<name>.png
```

像摄影师的提示一样提示：一个具体的主题、地点、光线和镜头（*撒满面粉的钢柜台上放着一堆黑麦面包，左边的早期窗户光，50毫米，浅深度*），*没有文字，没有人面对相机*。查看每一个结果；六个手指、双层家具和融化的标签都回来了。处理和框架与图书馆照片相同。设计记录 `generated: <model> via imagegen.mjs`。切勿自动开火。
