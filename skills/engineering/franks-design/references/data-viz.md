# 数据可视化：按设置而非生成的方式读取的图表

当提示涉及图表、数据或仪表板，或者形状为 Stat-Led 或 Workbench 时加载：表格脊柱、细线网格、一系列争论，并且没有装饰性仪表板（没有甜甜圈墙、仪表行或 KPI 五彩纸屑）。

## 先形成表格（在任何绘图之前）

| 数据是 | 形式是 |
| --- | --- |
| 一个值 | 统计图块（一个大数字和一个措辞限定符），而不是一个条形图 |
| 比较两到五个值 | 统计行或水平条 |
| 随着时间的推移一系列 | 一条线，或者当它位于另一个组件内部时的迷你图 |
| 超过大约七个类别 | 一张桌子；更多颜色并不是答案 |
| 整体的一部分 | 堆叠的单杠；从来没有馅饼、甜甜圈或仪表 |

最未充分利用的形式是强调：一个重音系列，其他一切都是中性的。如果每个系列都很响亮，那么没有一个系列是响亮的。

## 构建（为数据编写的内联 SVG，无图表库）

- **条形**：<= 24px 粗，2-4px 间隙，基线始终为零；仅在数据末尾舍入，<= 2px。
- **线路**：2px行程；标记仅位于注释点 (>= 6px)；迷你图可以淡入淡出填充为透明，这是图表附近认可的渐变。
- **网格线**：1px 实心 `--color-rule`，从不虚线，比您想象的 (3-5 horizontal lines) 少；轴线可以是网格的第一条线，而不是较粗的笔画。
- **一个 ​​y 轴。** 切勿使用双轴，这是伪造相关性的经典方法。两个具有不同单位的系列会得到两个小图表（小倍数）。
- **无标记阴影、无 3D、标记中无渐变**（迷你图淡入淡出填充除外）。
- 组件内的迷你图：没有轴，没有网格，没有第二种颜色。

## 颜色

适应 Hallmark 的单重音规则（8 色调分类调色板将与页面上的其他所有内容相抗衡）：

- **单系列**：重音。
- **多系列**：强调色调的亮度渐变（​​L 步长约为 12-15%，色度常数），按固定顺序分配，从不循环； `--color-muted` 中的上下文/参考系列。
- **第二种色调**仅在全调色板姿势下，来自已声明的角色，从未在图表中发明。
- **文本永远不会磨损数据颜色。** 标签、值和轴文本为 `--color-ink` / `--color-muted`；一个系列是通过标签旁边的样本来识别的，而不是通过对文字进行染色来识别的。
- **每个数字表面上都有表格数字** (values, axes, tables; F6)。

## 诚信 (gate 46a binds here hardest)

- 实数，或缺少数字的文本槽 (`craft.md` § 8)；编造的系列比空的插槽还要糟糕。
- 条形从零开始；夸大增量的截断轴是发明指标的数字版本。当数据真正位于窄带中时，明确注释缩放视图（“轴从 94% 开始”）。
- 样本数据仅存在于构建的产品样本或代码表面内，作为样本读取（总和、日期序列），并且绝不是访问者可以作为声明的数字 (`craft.md` § 6)；设计记录纸币 `data: sample`。

## 黑暗的

标记重新派生为 [`dark-mode.md`](dark-mode.md) 中的重音符号（色度向下，L 向上）；来自黑暗的网格线`--color-rule`；在深色背景上，淡入淡出填充的不透明度降至一半。

## 仪表板栏

工作台或仪表板构建显示更少、更真实的图形：一个首屏主视觉人物（统计图块）、一个支持图表、一张表格。带有六个仪表的 KPI 墙告诉我们此文件的存在是为了杀死它。
