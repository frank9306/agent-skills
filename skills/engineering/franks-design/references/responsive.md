# 反应灵敏

已加载以适应不寻常的布局。没有仅限桌面的交互；每个页面在 320 到 1920 CSS 像素范围内都可以正常渲染。

## 脚本检查什么以及不能检查什么

sloplint 覆盖了 320、375、414、768、1024、1280、1440 和 1920 的机械部分：水平滚动和 `overflow-x: clip` (34)、环绕控件 (49)、图像轨道和显示头 (50)、无线电选项卡 (53)、堆叠粘性元素 (56)。通过眼睛检查每个宽度看不到的内容：每个桌面侧边栏或过滤器列都会折叠成菜单或披露，章节标题堆叠到一列，每个主题覆盖都有自己的移动规则。

## 断点

第二，由整个页面共享，在 `rem` 中，因此它们遵循用户的字体大小。脚手架在两个位置都降低了其标记：在 60rem (about 960px, the layout breakpoint) 下，页边距下降到 24px，三个部分间隙下降到 80、96 和 120px；在 40rem (about 640px, the type breakpoint) 下，页边距降至 16px，截面间隙降至 56、72 和 96px，列间隙降至 16px。在整个页面的一个方向上针对相同的两个宽度编写组件规则。仅在内容本身中断的地方添加第三个。

- **在 60rem 下：** 多列网格转到一列，倾斜和剪辑效果下降，粘性窗格脱离，每个首屏主视觉姿势折叠到内容高度（海报可能保持全屏）。
- **在 40rem 下：** 显示尺寸减小，边距标题内联移动，注释合并。

## 流体和离散

`clamp()` 用于连续变化的尺寸（秤的显示标记已经这样做）；针对离散变化的布局的媒体查询。使用 `@media (hover: hover)` 和 `(pointer: coarse)` 检测功能，从不使用宽度：

```css
@media (hover: hover) { .link:hover { text-decoration-thickness: 2px; } }
@media (pointer: coarse) { .btn { min-height: 48px; } }
```

与机身相邻的 UI（元、导航链接、控件）在手机上运行得更大，并在 60rem (`craft.md` § 9) 处收紧。

## 可点击的文本永远不会换行

按钮、主要导航链接和 CTA 在 320 到 1920 (49a) 的每个宽度上都是单行；页脚链接、选项卡和面包屑也是如此，除非真正的短语不能缩短 (49b)。当一个包装时，按以下顺序：

1. **缩短标签。** *免费开始* 改为 *免费开始*； *阅读文档*以*阅读文档*。
2. **`white-space: nowrap`** 在控件上，并让其周围的行重排。
3. **折叠行**，而不是标签：在 60rem 下，不再适合的链接位于菜单后面，而两三个适合的短链接则保留在栏中。

## 单位和安全区域

- `dvh` 或 `svh` 的高度符合移动浏览器 chrome 的要求，绝不是 `vh` 位于首屏主视觉 (6a) 上； `width: 100%`，绝不是`100vw` (34)。
- 使用 `viewport-fit=cover`，将安全区域折叠到装订线标记中：`--gutter: max(16px, env(safe-area-inset-left))`。

## 表格、图像、语言

- 手机上的**表格**将命名行的列和对其进行操作的列保留在视图中：将每行重新堆叠为标记块，或固定第一列 (`craft.md` § 9, F25)。手机上的十列是重新设计，而不是挤压。
- **图像：** 具有宽度描述符的 `srcset`、用于不同裁剪的 `<picture>`、每个图像上的 `width` 和 `height` 属性、`loading="lazy"` 位于折叠下方且绝不位于 LCP 元素上。
- **语言：** 逻辑属性（`margin-inline-start`、`padding-block`）、可容纳 30% 到 40% 长字符串的空间，无硬编码日期或数字格式。

从不：设备嗅探而不是功能查询、仅悬停交互、`px` 中的断点。
