# 图像

页面显示的内容，请阅读每个页面构建。当页面显示真实的东西（地点、食物、物体、工作人员、运行的产品）时，页面看起来像是制作完成的；当页面显示渐变框、面包图或下面没有任何内容的标题时，页面看起来像是生成的。

## 1. 什么填满一页

按顺序，第一个适合的：

1. **用户自己的图像和录音**，在步骤 1 中要求。他们赢得了每个插槽。
2. **真实产品的屏幕截图**，每当可以访问产品时，构建本身都会拍摄：URL、正在运行的开发服务器、以一个命令启动的文件夹中的项目、本机 (§ 4) 上的桌面或手机应用程序。真实的屏幕胜过任何图片。
3. **仅当尚无产品可捕获时才构建产品 (§ 4)。
4. **来自图书馆的照片**，由脚本挑选并以主题方式处理 (§ 2, § 5)。
5. **生成剧照**，仅当设置了 `TOGETHER_API_KEY` 并且用户要求提供 (§ 6) 时。
6. **当提示有关单词时，以全尺寸键入**。

哪个提示需要哪个：

- **地点、材料、食物或饮料、物品、工艺品、户外、活动、工作人员**（面包店、滑雪学校、杜松子酒、编织工作室、场地、裁缝、农场）：照片引导。首屏主视觉的照片是第一个屏幕上最大的东西（在头部后面全出血，或者在头部旁边，占屏幕高度的 60% 到 75%）。之后，还有两到四张纸页，其中一页很大，每页都有其主题（一张偏离主题的图片被剪掉，从来没有保留来填满计数），它们之间只有材料的各个部分（菜单或价目表作为行，时间和地点作为表格，声明，表格），因此图片占据了页面 (§ 5, 83) 的四分之一到三分之一。
- **软件**（SaaS、应用程序、开发人员工具）：产品主导，主要视觉效果是其界面。当每张照片通过删除测试时，一两张照片可能会设定场景（它在哪里使用，它处理的材料，它所服务的工作）：将它拿走，页面就会失去一个事实。夜晚的城市、办公桌上或办公楼上的笔记本电脑都无法正常工作。
- **文字**（文档、API、CLI、类型样本、宣言或关于想法的信件）：类型和代码携带它；最多一张照片作为全出血带。关于物理事物（修理、河流、街道）的宣言或信件就像任何其他页面一样显示它。

照片永远不会代表事实：数字、姓名和声明保持不变，人的照片永远不会代表客户、团队成员或推荐 (F9)。

## 2. 图书馆

Hallmark 包含来自 Wikimedia Commons 的 755 张经过验证的照片，每张照片均是 CC0、公共领域、CC BY 或 CC BY-SA，并按主题、色调和温度进行标记。询问页面需要的每个主题，具体来说：

```
node <skill-dir>/scripts/theme.mjs photos "apple orchard in autumn" "hands picking apples" --theme <slug> [--n 3] [--orient portrait|landscape|square] [--seed <draw seed>] [--log .hallmark/log.json]
```

它对每个主题的库进行排名，避开最后五个版本使用的照片，并为每个选择打印它所显示的内容、其大小、准备好的 `<img>` 及其 `srcset` 及其信用。只保留适合该部分的句子的选择；换句话说，在侥幸逃脱之前重新询问（地点、材料、动作）。

- **永远不要凭记忆编写图像 URL 或从库存网站获取图像**（Unsplash、Pexels 和 Pixabay，用他们的话来说就是人工智能驱动的选择）。仅使用脚本打印的内容或用户提供的 (76)。
- **每张图书馆照片的出处：** 页脚中标有 `data-credits` 的一行（预算一词会跳过它），*照片：* 然后以页脚的小样式打印每张出处。 CC BY 和 CC BY-SA 需要 (76)。
- **CSS 中的尺寸和裁剪：** 保留打印的 `srcset`，将 `sizes` 设置为布局（`50vw` 为半出血，`100vw` 全出血），并使用框架进行裁剪：插槽上的 `aspect-ratio`、`object-fit: cover`、打印的 `object-position`（或您自己的）以使主题保持在框架中。
- **对于生产，** `--save <dir>` 将选取项下载到项目中并打印本地路径；草稿可以链接共享缩略图。
- **首屏主视觉照片是 LCP：** `fetchpriority="high"`，绝不是 `loading="lazy"`；其他所有图像都是懒惰的。全出血或首屏主视觉框架在其长边上拍摄 2400px 或更多照片； 1920 年，较小的一个变软。
- **替身保持可交换：**在其插槽 (§ 3) 中，`data-alt` 命名用户自己的图片应显示的内容，在交接中列出。
- **无节点：** 在“选择”块中如此说，并仅将插槽与用户的材料一起使用；永远不要猜测文件。

## 3. 老虎机

插槽是用户将替换的任何图片：`data-slot="<name>"`（`hero`、`demo-2`、`photo-1`）、`data-alt` 说明属于该位置的内容，以及实际尺寸（`aspect-ratio` 或固定高度）。脚手架的`base.css`持有插槽CSS，脚手架打印`hallmarkSlots`脚本：在`</body>` (F18)之前粘贴一次。它会在不触及布局 (`hallmarkSlots({ hero: 'shop.jpg' })`) 的情况下交换用户的文件，并删除无法加载的替身。

- **插槽总是显示一些内容：**用户的图像、图书馆照片或完全保真度构建的产品。它的洗色（`--color-paper-2` 到 `--color-paper-3`）只是加载照片时背后的颜色；一个槽位什么也没有显示，但它的水洗是一张空图片 (81)。
- **没有可见的占位符标签：**没有“此处的屏幕截图”、比率注释或“样本”芯片； `data-alt` 和切换都可以实现这一点。
- 一旦用户的图像登陆（信用、车牌号），必须留下来的孩子携带 `data-keep`；开槽照片（海报首屏主视觉的头部和稀松布）上的文本位于槽 (`z-index: 2` or more; the slot's image takes 1) 上方的同级层中，但从未位于其中。
- 连续的槽位不得超过四个，也不得为页面上没有图片的事物设置一组框架（团队、场地列表）：将其设置为 (68) 类型。

## 4. 产品：首先捕获，仅在无法捕获时才构建

**捕获它。** 当产品存在时，页面会显示它，而不是它的模拟。在步骤 0 中找到它：提示符中的 URL、已运行的开发服务器、带有 `dev` 或 `start` 脚本的 `package.json`、计算机上构建的应用程序或用户名的路径。如果需要启动（安装、运行、等待端口），则启动它，将其置于讲述页面故事的状态（示例数据、打开的真实项目、完成工作的一个屏幕），然后：

```
node <skill-dir>/scripts/capture.mjs http://localhost:3000 --routes /,/settings --sizes desktop,phone [--selector ".editor"] [--full] [--out images/screens]
```

它以 1440 x 900 和 390 x 844 写入 2x PNG（或一个带有 `--selector` 的元素），并为每个 PNG 打印一个 `<img>`。基于 Electron、WebView2 或 CEF 构建的桌面应用程序通过 DevTools 端口启动并通过它捕获（`capture.mjs --cdp 9222 --target "<window title>" [--selector ...]`，干净且以其自己的像素密度）；具有操作系统的任何其他桌面应用程序（macOS 上的 `screencapture -l <window id>` 或 `-R x,y,w,h`）、带有模拟器的手机应用程序 (`xcrun simctl io booted screenshot`)、通过运行它并在代码块中设置其实际输出的终端工具。在发货前查看每个捕获：屏幕上没有任何个人内容（名称、电子邮件、令牌、文件路径），没有错误状态（除非它们是重点），没有调试覆盖。使用几个：首屏主视觉的主屏幕、下部大裁剪的细节、第二个屏幕、手机视图。盖章 `imagery: screenshots <n> (capture.mjs)` 且不注明任何内容；它们是用户自己的。

**将其框架在主题中。** 捕获位于具有主题半径和插入轮廓 (§ 5) 的 `data-slot` 中，绝不会位于绘制的浏览器栏、设备框架、交通灯或缺口 (47a, 47b) 内。裁剪到销售部分（`object-position` 或 `--selector`），使其中的文本以其显示尺寸 (scale 2, never upscaled) 清晰可见，并且切勿修改产品显示的内容。捕获的是产品图片：标记其插槽 `data-kind="product"`，因此它们不计入照片余额 (83)。

**仅在无法捕获时才构建它**（一个想法，尚未构建的产品，无法访问）：首屏主视觉视觉效果是用 HTML 和 CSS 构建的产品主屏幕：真实控件，至少八个元素，提示的名词，主题的表面和类型，尺寸为 `layout.md` § 6 给出了视觉效果。样本值读取为样本（`example.com`，*示例厨房*，四舍五入合理数量），绝不是访问者可以将其视为索赔 (46a) 的数字。它位于 `data-slot` 中，因此真实的屏幕截图取代了它，并且切换说明了产品运行后要捕获哪些屏幕。切勿构建本可以捕获 (84) 的产品的模拟。

工作控件（用户价格计算器、预订表格）是一个精细的部分和一个精细的结束，一页；它不是默认首屏主视觉。

## 5. 放置和处理照片

- **大或根本不大。** 照片跨越十二列中的六列，高度为 440px 或更高，或者采用全出血；在缩略图大小时，它读起来就像剪贴画（一组四个或更多可能会更小，每个都有它的事实）。在首屏主视觉中，它位于文本旁边的屏幕高度的 60% 到 75%，或者填充在头部后面的屏幕（海报姿势）。删除头脑中的图片：如果屏幕仍然显示相同的内容，则图片太弱或太小。
- **一个主题一个框架，剪得很紧，**它的重量倾向于文本。改变 (4:5 beside text, 16:9 or 21:9 across, 1:1 in a pair) 的比例和尺寸（8 列和 4 列；三个相等的框架仅用于真正的设置：三个盘子，三个房间）。
- **平衡。** 在首屏主视觉下方，照片最多占页面的三分之一，分辨率为 1440（已构建产品内的图片，标记为 `data-kind="product"`，不算在内），在摄影或作品集网格形状上最多占 45%；过去该页面显示为库存画廊，并且主题从不讲 (83)。切勿连续两个以照片为主导的部分：在图片后面加上主题类型、规则、颜色或产品单独携带的部分（主题文件的范围）。软件页面将产品与类型引导的部分交替显示，并拍摄一张或两张照片；一个以单词为主导的页面最多需要一个。如有疑问，请剪掉最薄弱的图片并将其事实放大。
- **照片上的文字**位于主题墨水的稀松布上最平静的部分（从文本边缘渐变，35% 到 65%），仅位于文本侧面后面，与下方图像的比例为 4.5:1 或更好；永远不要将白色字体放在繁忙的框架上。拒绝渐变的主题使用固体墨板。
- **图片上的事实：** 标题是来自图片旁边或下方的标签样式提示的事实（菜肴及其价格、房间及其营业时间、日期、地点）。那里从来没有信用额度，也没有声称替身是用户自己的人、地点或产品的标题。
- **主题的处理，在每张照片上。** 主题的 `photo:` 标头设置它，支架将其作为插槽中每个图像上的 CSS 写入 `base.css`，用户自己的包括：`natural`、`warm`、`muted`、`mono`、`duotone` 在两个主题的设计令牌，或 `tint` 合而为一，并进行调整（`con=`、`sat=`、`exp=`）。双色调或色调将苍白的主体（雪、白墙）变成一个空旷的区域：选择具有色调范围的框架，并通过处理来观察每个框架。双色调或色调采用插槽的 `::before`，因此请使用 `::after` 或同级产品绘制键线或稀松布。仅当页面添加了内置产品内的照片时，才会对其进行处理。
- **框架是主题的：** 它的半径、6 到 10% 的墨水插入轮廓 (`outline: 1px solid ...; outline-offset: -1px`)、它的纹理（如果有）。永远不要将边框和宽阴影放在一起 (F24)。

## 6. 生成的剧照

仅当设置了 `TOGETHER_API_KEY` 并且用户要求生成图像或库无法访问的主题时：`comp.md` § 生成的静态图像。切勿自动开火。

## 7. 绝不

- **绘制的插图** (80)：超过图标大小的物体、植物、动物、人、产品、建筑、景观或场景的 SVG 或 CSS 图形。 SVG 适用于一组图标、用户徽标、真实数据的图表和图表或带有标签的真实系统，以及简单的几何图形（规则、网格、作为纹理的点图案）。
- **空图片** (81)：仅显示洗涤效果的插槽，或图片应在的渐变字段。
- **计数装置** (82)：一排或一格相同的标记代表一个数量，每个瓶子或每天一个。设置号码。
- **插图包和人物：** unDraw、Humaaans、Storyset、Lottie 吉祥物、3D 斑点、等距场景。
- 库存面为证明 (F9)；没有用户徽标的徽标墙 (46a)；文本 (29) 后面的网格斑点、球体或极光；悬停时缩放或旋转的图像 (11)；文字被烘焙成图片；显示他人界面的屏幕照片。

## 8. 图标、徽标、视频、3D

- **图标：** 一页一个库（默认情况下为 Lucide；使用它们的项目中的 Phosphor 或 Heroicons），一个笔划宽度和一种样式，位于集合网格 (a 24 viewBox at 24px, never scaled to 19)、`currentColor` 上的 16、20、24 或 32px，与多行文本的第一行对齐，绝不在彩色图块中 (3, F5)，绝不是表情符号(30a)。带有图标的按钮通过垂直填充来填充图标一侧。
- **标志：**用户自己的，单色，一排一个处理，32到48px高(20 to 28px in a footer)；简单图标（`https://cdn.simpleicons.org/<slug>/<hex>`）仅用于平台或品牌页面名称。从来没有发明过墙 (46a)。
- **视频：** 用户的录音或镜头：`autoplay muted loop playsinline` 与 `poster` (28a, 28b)、AV1 或 VP9 WebM，然后是 H.264 MP4，小于 2 MB，持续 10 秒，任何循环超过 5 秒时有可见的暂停控制，说话时有字幕。
- **3D 和 WebGL** 仅当产品是 3D 并且访问者可以处理它时，仍然有后备。
- **动画库：** 首先是 CSS 和 `@property`； React 中精心策划的入口动作；仅当时间线是产品时才采用 GSAP。

## 9. 设计记录、日志和移交

钢印`imagery: photographs, library 5, mono · product sample in hero and demo-2`（或`imagery: none`）；日志的 `imagery` 字段包含相同的单词，而 `photos` 则使用 ids，因此下一个构建的选择会轮换。交接会列出每个替身和构建样本及其插槽、大小以及用户自己的图片应显示的内容。
