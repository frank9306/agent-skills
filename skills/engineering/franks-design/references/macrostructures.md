# 宏观结构

二十一个命名的登陆页面形状。每个指纹都是一个完整的指纹（标题位置、正文构成、分隔符语言、按钮声音、图像处理、显示模式），捆绑在一个名称下。 **这是一个词汇表，而不是菜单。** 设计提示要求的页面，然后命名您设计的形状，以便旋转和门 32 有东西可读；首先到达这里并建造任何返回的东西就是二十一个形状折叠成相同的三个的方式。如果这里没有任何东西符合您的设计，请说出来，将形状描述为指纹（§指纹，如下），并为设计记录和日志指定一个简短名称（*季节页面*）。

## 21个宏观结构、指标

**只读您所找到的形状的一个文件**，来自 `references/macrostructures/`。不要加载整个目录。蛞蝓稳定；旋转从设计记录和日志中读取形状。导航和页脚是形状的一部分，与首屏主视觉一起解决。每个形状文件都会为其构建的 `layout.md` 组合命名；代码是你的。

- **01 · 便当网格。** 不同尺寸的模块块排列成不规则的网格。每个块都是一个特征、一个图形、一个图像或用户提供的引用。节奏来自于大小变化，而不是卡片的一致性。 [`macrostructures/01-bento-grid.md`](macrostructures/01-bento-grid.md)
- **02 · 长文档。** 读起来像备忘录、信件或日记条目。没有营销结构。带有内联章节标题的连续散文。该页面是有关该产品的文献。 [`macrostructures/02-long-document.md`](macrostructures/02-long-document.md)
- **03·选框首屏主视觉。** 首屏主视觉是首屏页面。单个语句或视觉效果填充视口。在折叠之下，页面变成了其他东西（列表、网格、散文）。 [`macrostructures/03-marquee-hero.md`](macrostructures/03-marquee-hero.md)
- **04 · Stat-Led.** 首屏主视觉是用户给出的人物，并有一行文字说明其含义。接下来的一切都支持或限定它。 [`macrostructures/04-stat-led.md`](macrostructures/04-stat-led.md)
- **05 · 工作台。** 真实产品捕获是主要内容。该页面是正在使用的应用程序的导览，并用简短的标题代替了营销文案。 [`macrostructures/05-workbench.md`](macrostructures/05-workbench.md)
- **06 · 对话式常见问题解答。** 大胆提问，及时解答。该页面读起来就像是对产品的诚实采访。每对都可以是一个披露。 [`macrostructures/06-conversational-faq.md`](macrostructures/06-conversational-faq.md)
- **07 · 宣言。** 争论性的大字体。该页面先告诉读者该相信什么，然后再告诉他们该买什么。 [`macrostructures/07-manifesto.md`](macrostructures/07-manifesto.md)
- **08 · 摄影。** 每个折叠处都有一张巨大的图像。文字是小注释，不是标题。该设计在说“阅读”之前先说“看”。 [`macrostructures/08-photographic.md`](macrostructures/08-photographic.md)
- **09 · Quote-Led.** 首屏主视觉是用户提供的引用及其归属。标题是别人的声音。 [`macrostructures/09-quote-led.md`](macrostructures/09-quote-led.md)
- **10 · 样本。** 大衬线显示、不对称跨度、细线规则、印刷 CTA、大量空白。仅用于有关类型、出版或写作的提示（铸造厂、期刊、出版社）；仅凭社论类型是不符合条件的。 [`macrostructures/10-specimen.md`](macrostructures/10-specimen.md)
- **11 · 目录。** 同一事物的变体的统一网格：字体、调色板、SKU。该页面是库存的直观索引。 [`macrostructures/11-catalogue.md`](macrostructures/11-catalogue.md)
- **12 · 信。** 第一人称，书面的，亲密的。以问候语开头。读作创始人的个人笔记。 [`macrostructures/12-letter.md`](macrostructures/12-letter.md)
- **13·索引优先。** 该页面是链接列表。没有首屏主视觉形象，没有叙事流程。导航作为设计。 [`macrostructures/13-index-first.md`](macrostructures/13-index-first.md)
- **14 · 叙述工作流程。** 编号的阶段讲述了用户如何随着时间的推移使用产品的故事。每个部分都是一个阶段；该页面是一个流程时间线。 [`macrostructures/14-narrative-workflow.md`](macrostructures/14-narrative-workflow.md)
- **15·分割工作室。**双联画。每个主要块都划分屏幕，一侧是文本，另一侧是证明；校样保持其侧面，行数随重量而变化。 [`macrostructures/15-split-studio.md`](macrostructures/15-split-studio.md)
- **16 · 功能堆栈。** 粘滞的左窗格包含标题，滚动同步的右窗格循环显示相关捕获。像电影一样节奏。 [`macrostructures/16-feature-stack.md`](macrostructures/16-feature-stack.md)
- **17 · 类型样本。** 字体就是设计。铸造页面和设计系统，其中自定义面孔就是证明。 [`macrostructures/17-type-specimen.md`](macrostructures/17-type-specimen.md)
- **18 · 投资组合网格。** 可过滤的项目卡。工作室和设计师主页，其中的作品就是产品。 [`macrostructures/18-portfolio-grid.md`](macrostructures/18-portfolio-grid.md)
- **19 · 地图/图表。** 单个大型空间图组织页面：流程图、平面图、网络图、系统图。 [`macrostructures/19-map-diagram.md`](macrostructures/19-map-diagram.md)
- **20 · 生态系统指数。** 多个发现表面：特色、最新、按类别、按人员。平台的价值在于浏览，而不在于声明。 [`macrostructures/20-ecosystem-index.md`](macrostructures/20-ecosystem-index.md)
- **21 · 组件游乐场。** 交互式代码和预览块是页面的主要内容。每个块都会预览一个事物并显示如何复制它。 [`macrostructures/21-component-playground.md`](macrostructures/21-component-playground.md)

## SaaS 部分：处理它，而不是排序它

当形状是 **Bento Grid、Stat-Led、Workbench 或 Marquee Hero** 并且提示是 B2B SaaS 页面时，请从此平台构建。卡牌有角色，但没有位置。甲板的基础是由页面可以诚实地显示的东西组成的，而不需要发明任何东西；甲板的顶部仅在用户交出材料时才存在。

**基础卡**（始终可用）：

| 卡片 | 角色 | 作品 |
| --- | --- | --- |
| 规格表 | 它是什么，产品附带的数字：限制、格式、版本、区域 | 表或行 (`layout.md` § 5) |
| 工作示例 | 产品在用户的材料上做一项真正的工作：命令及其输出、捕获及其标题 | 展示或拆分 |
| 变更日志 | 最后三或四个条目及其真实日期；该页面证明它还活着 | 行数 |
| 比较解剖 | 产品旁边是今天的做法，逐行，没有分数 | 桌子 |
| 定价表 | 实际价格，两级或三级；每一层的“联系销售人员”都表示该品牌不信任买家 | `craft.md` § 9 定价 |
| 常问问题 | 像一个人一样回答真正的反对意见； “是的，两个提供商都可以开箱即用”击败“与领先提供商集成” | [`macrostructures/06-conversational-faq.md`](macrostructures/06-conversational-faq.md) |
| CTA条带 | 询问，一次，一键 | 乐队 |
| 页脚 | 结束，在主题的声音中 | `layout.md` § 7 |

**材料卡**（仅当用户提供材料时才存在，并且“选择”块命名所提供的内容）：

| 卡片 | 需求 | 没有它 |
| --- | --- | --- |
| 首屏主视觉视觉 | 真实的捕捉 | 产品内置 `data-slot` (`imagery.md` § 4) 或印刷首屏主视觉；永远不会在插槽之外使用 styled-div UI (47c) |
| 标志行 | 用户自己的客户标记，有权显示它们 | 该卡不存在；无发明标记，无“受信任”行 (46a, 54) |
| 三大特点 | 三个命名功能，每个功能都有一个捕获或图形来显示 | 将它们折叠到工作示例或规格表中 |
| 感言 | 逐字引用用户提供的信息，并给出该人的姓名、角色和公司 | 该卡不存在；没有合理的名称，没有释义 (46a, 19) |

**每笔交易都会出现两次偏差。** (a) 放下至少一张基本卡并为其命名（CTA 条是通常的剪切方式；页脚永远不会掉落）。 (b) 将第二张基本卡提升到首屏主视觉位置（首屏主视觉对象说“数字就是音高”时的规格表；首屏主视觉说“看它工作”的工作示例）或有意义地重新排序相邻的一对（示例中说“价格就是音高”之前的定价）。在设计决策清单中说明这两个动作：`deck: -cta +changelog` 或 `deck: -faq · pricing<example`。至少保留五张牌的交易仍视为完成；低于五的它是着陆条，而不是着陆页：重新添加卡片或切换形状。

卡片由三个 `--section-gap` 步组成，混合 (59)，并且每个都填充其部分 (`layout.md` § 4)。

牌组不是您印出的模板：形状决定了每张牌的外观。 Bento 网格页面将规格表和示例交错在网格内；统计引导页面在图下从上到下对它们进行排序；选取框首屏主视觉页面让选取框包含声明，示例包含证据。

对于非 SaaS 工作（社论、宣言、信件、长文档、报价引导），此套牌不适用。面包店不需要进行定价等级比较。

## 如何挑选

在主题构建上绘制了形状 (SKILL.md Step 2)；这些步骤用于交换材料力，或在没有 Node 的情况下运行。

0. **读取材料库存** (SKILL.md Step 2)。基于屏幕截图或图形构建的形状需要它们，无论是真实的还是用户要求的插槽；两者都没有，选择一个带有类型和事实的形状。
1. **阅读提示。** 注意任何强烈暗示一种形状的词语（“数据重”、“讲述一个故事”、“链接列表”、“许多小功能”、“个人注释”）。
2. **读取 `.hallmark/log.json`**（最新的在前）以及项目中任何 Hallmark 标记的 `shape:` 字段；最后三个形状被排除。
3. **使用上面的索引线和下面的§域将提示与形状匹配**，然后仅打开您所在的文件。大多数提示匹配 2 到 4 个；选择距离记录形状最远的一个，然后检查 SKILL.md 第 2 步中的镜像测试。
4. **在“选择”块的“形状”行和设计记录的“`shape:`”字段中陈述一次选择**。
5. 如果撕裂，则取出该域的三重奏（§域到三重奏）并选择距离原木最远的一个。

为两个不同提示构建的两个页面 Hallmark 必须看起来像不同的站点，而不是一个模板的颜色交换。

## 指纹：六轴

**1.标题位置。** 左边距 (marginalia beside the body; a label beside a heading is an eyebrow, gate 54) · 悬挂（标题漂浮在空中） · 居中显示 · 底部对齐（标题固定在底部，内容在上面） · 重叠（在照片或色块上） · 粘着或固定 · 按结构编号（带有 `counter()` 的真实 `<ol>`，或图形比例的一个数字） · 与正文对齐（无中断，标题出现）来自散文）。任何安置都是公平的；读起来是错误的，是在全角左对齐内容上出现狭窄的自动居中头部。

**2.正文组成。** 单栏 · 两栏不对称（正文宽，标题边距窄） · 多栏通过连字符对齐 · 旁注（外边距中的旁注） · 三等分栏（参考密度） · 带边距重置的全出血 (65ch body, pull quotes and images bleed) · 不对称跨度 (2-1-3 ratios on a grid)。

**3.分隔线语言。** 细线规则（0.5 到 1px，插图或全出血） · 装饰（花、点、标记） · 负空间（间隙是分隔线） · 出血色块（纸张变化是边缘） · 双规则。为页面选择一种语言，并通过接缝改变其粗细和位置 (9)：每个接缝处相同间隙的相同规则就是模板。

**4.按钮语音。** 实心（一个填充的主要内容） · 轮廓线 · 无样式链接（带下划线的单词） · 超大实心 · 仅排版（粗细中的单词，无方框） · 形式为 CTA（操作为填充此字段）。

**5.图像处理。** 全出血 · 紧密裁剪到网格 · 与文本内联 · 边距对齐 · 无。

**6。显示模式。** 淡出交错（一次，精心安排） · 水平扫描 · 类型取消屏蔽（在文本上打开剪辑路径） · 数字刻度（计数器，仅在真实数字上） · 打字机（仅终端，键入命令内的插入符号） · 无。

指纹：每轴一个选择，写为 `Hanging|Asymmetric spans|Hairline|Outlined|Margin-aligned|None`。两条规则：连贯性（来自同一个世界的选择；合理的报纸机构需要印刷 CTA，而不是超大实体）和反重复（与最后三个记录条目中的任何一个共享的六个轴中不超过三个；图像或显示上没有，表明主题或物质力量不是共同的选择）。

## 域为三重奏时，提示名称无形状

来自不同系列的三种形状（网格主导、文档主导、海报主导、产品主导）适合该领域，而不是三个近乎双胞胎；距离最后记录的形状最远的是选择：

| 领域词 | 三人组 |
| --- | --- |
| 播客、音频、音乐、聆听 | 摄影 · 引言 · 信件 |
| 商店、商店、产品、商品、商业 | 目录·摄影·便当网格 |
| 文档、CLI、SDK、API、库、开源 | 工作台·长文档·组件游乐场 |
| 平台、基础设施、可观察性、B2B 工具 | Bento 网格 · 工作台 · Stat-Led |
| 机构、工作室、案例研究、作品集 | 投资组合网格·拆分工作室·索引优先 |
| 个人寻呼机、关于我、简历 | 长文档·信件·索引第一 |
| 餐厅、咖啡厅、酒吧、食物、菜单 | 摄影·长文档·目录 |
| 时尚、服饰、美容、Lookbook | 摄影（有实拍）·目录·跑马灯首屏主视觉 |
| 金融科技、银行、支付、交易 | Stat-Led · 工作台 · 长文档 |
| 宣言、运动、事业、倡导 | 宣言·报价主导·统计主导 |
| 社论、铸造厂、杂志、类型 | 样本·长文档·类型样本 |
| 产品发布、SaaS营销 | Bento 网格 · 工作台 · Stat-Led |
| 会议、活动、演讲者 | 字幕首屏主视觉 · 宣言 · 摄影 |
| 根本没有信号 | 便当网格 · 长文档 · 宣言 |

开发人员文档和开发人员营销是不同的提示（演练需要 Workbench；落地需要 Bento 加 Stat-Led），单页阅读器和案例研究组合也是如此；步骤1的用途决定。一个模糊的语气词（“现代”、“干净”）通过流派来阅读并作为推论陈述，而不是第二个问题。
