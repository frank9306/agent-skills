## 2026-11-09

### Changed

<!-- app-use status bar batch 1; no ISSUE created yet -->
- Hardened app-use deterministic contracts: fixed the `grantUniversalAccess` parameter, made dialog-interrupted input report `actionExecuted:false` instead of a false success, raised the OOPIF frame drain limit to a named constant, rejected unknown CLI flags and commands before connecting, let branch rules fall through to `otherwise` when a target is absent, and bound local evidence to the published `AppUse.exe` hash plus an append-only run ledger.
- Added `test:app-use:live`, a status bar event consumer with unit tests, the frozen visual baseline and the status event contract. The .NET event publisher and Win32 status window are not implemented, so the consumer is intentionally not wired into the production CLI.
- Clarified the README Node 20+ requirement and the separate app-use bridge acceptance path; documented the work-in-progress boundary in `support.md`.
- Implemented the native Win32 status bar overlay with two interchangeable backends — a Go build (`native/StatusBar/main.go`) and an Add-Type/PowerShell P/Invoke implementation (`native/StatusBar/status-bar-native.ps1`) — sharing the same JSON event protocol and the same extended window styles (`WS_EX_NOACTIVATE|WS_EX_TRANSPARENT|WS_EX_TOOLWINDOW|WS_EX_TOPMOST|WS_EX_LAYERED`, measured `0x080800A8`). The host auto-selects the Go build when the machine allows it to run and falls back to PowerShell when Smart App Control blocks unsigned executables.
- Added Windows UI Automation desktop automation (`native/MoleUI/mole-ui.ps1`) driving the Mole cleanup app through its real WinUI 3 interface, plus the end-to-end verification script `scripts/mole-cleanup.mjs`. Verified live against Mole: the clean tab, preset selection and the final clean button are clicked by AutomationId, and Mole's own `operations.jsonl` confirms the cleanup (94/94 items, 0 failed).
